# V2.0 RAG 质量体系封板设计文档

更新日期：2026-07-26

## 摘要

V2.0 将每次 RAG 评估运行转化为可封板的质量证据。设计选择复用现有 `RagEvalRun.metrics` JSON 持久化和现有 Web RAG 评估面板，因此本版本不需要新增数据库迁移。

## 目标

- 将失败或退化评估信号持久化为反馈候选快照。
- 增加确定性答案质量裁判，覆盖 groundedness、引用完整性、拒答/无答案正确性和幻觉风险。
- 从运行证据中汇总检索实验维度。
- 汇总能解释来源覆盖问题的数据/索引治理信号。
- 将运行指标转换为 SLO 风格发布目标。
- 通过 canary promote/rollback 逻辑控制候选 profile 是否可推广。
- 输出一份引用证据 key 的发布报告，便于封板签核。

## 非目标

- V2.0 不新增专用反馈工作流表、评审分配队列、批量提升 UI 或流程历史。
- V2.0 不提供生产遥测采集服务、外部告警路由或租户级长期 SLO 后端。
- V2.0 不启用可选 LLM 裁判。
- V2.0 不实现完整实验注册表生命周期、负责人模型或推荐引擎。
- V2.0 不需要新增数据库迁移。

## Metrics 合约

| Key | 用途 | 关键字段 |
| --- | --- | --- |
| `releaseReadiness` | 汇总发布状态和证据要求 | `version`、`status`、`readinessScore`、`blockerCount`、`requiredEvidence`、`artifactKeys`、`recommendedAction` |
| `realQueryFeedback` | 保存不可变反馈候选快照 | `candidateCount`、`candidates`、`categoryBreakdown` |
| `experimentMatrix` | 记录本次运行观察到的实验维度 | `topKValues`、`profiles`、`retrievalModes`、`caseCount`、`evaluationCount`、`rerankEvidenceCount` |
| `answerQuality` | 输出确定性答案风险证据 | `judgeStatus`、`riskCases`、`groundedPassRate`、`hallucinationRiskCount`、`unsupportedAnswerRiskCount` |
| `onlineObservability` | 汇总 fallback、无答案、延迟和 profile 回归观察 | `fallbackRate`、`latencyP95Ms`、`degradedProfileCount`、`sloStatus` |
| `dataIndexGovernance` | 解释语料和索引证据质量 | `expectedSourceCoverageRate`、`missingSourceCount`、`multiDocumentCaseCount`、`ambiguousCaseCount`、`embeddingDimensions`、`governanceStatus` |
| `onlineSlo` | 将运行证据转化为发布目标 | `status`、`objectives`、`breachedObjectives`、`observed` |
| `canaryGate` | 决定候选 profile promote 或 rollback | `baselineProfile`、`candidateProfiles`、`profileGateStatuses`、`decision`、`reasons`、`shadowEvalRequired`、`rollbackPlan` |
| `v2QualityClosure` | 汇总封板状态和已完成能力 | `status`、`completedCapabilities`、`recommendedActions` |
| `releaseReport` | 给出发布建议和证据清单 | `releaseName`、`releaseGateStatus`、`canaryDecision`、`closureStatus`、`recommendedAction`、`evidenceKeys` |

## 关键规则

- 反馈候选只来自失败用例、citation-eligible 的引用失败，或有效 fallback 信号；字面量 `fallbackReason=none` 不生成候选。
- 候选 ID 优先使用已持久化 result ID，否则使用 run/profile/case 组合，避免多 profile 运行中冲突。
- 正确的 citation-ineligible hard-negative / no-answer 用例不计为幻觉风险。
- Canary promote 必须存在候选 profile；classic-only 运行可以作为证据，但不能作为 canary promote。
- Canary 会读取实际 `profileGateStatuses`；即使聚合指标通过，只要候选 profile gate 阻断，也会 rollback。

## Web 设计

RAG 评估面板沿用现有 Quality dashboard 布局，新增 V2.0 Quality closure、Online SLO 和 Canary gate 卡片，并在已有卡片中展示 V2.0 指标。Canary 卡片展示 profile gate 状态，便于直接看到候选 profile 为什么不能推广。

## 封板标准

API/Web 元数据为 `2.0.0`，本文档和实施文档存在，metrics 合约已实现并有测试覆盖，Web 看板能展示新增证据，最终验证门禁全部通过后，V2.0 可封板。
