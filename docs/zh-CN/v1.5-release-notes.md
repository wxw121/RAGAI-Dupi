# V1.5.0 版本说明

<!-- language-switch -->
[English](../en/v1.5-release-notes.md) | **中文**

> **中文说明：** V1.5.0 在保留现有检索执行模式的基础上提升 RAG 检索质量，并要求非经典检索配置通过当前索引修订版的质量门禁后才能成为默认配置。

V1.5.0 提升了检索质量，同时保留现有的 `VECTOR`、`HYBRID` 和 `RERANK` 执行模式。`CLASSIC` 仍是无条件默认配置；任何非经典配置要成为知识库默认值，都必须具备当前索引修订版对应的通过证据。

## 亮点

- Parent-Child 索引检索高召回子块，并返回完整的父级上下文。
- QA-assisted 索引生成数量受限的候选问答条目，并将 QA 命中展开回源块。
- 检索配置新增知识库级 `CLASSIC`、`PARENT_CHILD`、`QA_ASSISTED` 和 `COMBINED` 选项。
- Profile V2 使用一个可过滤的 Milvus 超集，使所有配置都基于等价的文档修订版进行比较。
- Combined 检索在可选 Rerank 前，对子块路由和 QA 路由应用加权 RRF。
- 当命中率或引用质量相对 `CLASSIC` 回归时，修订版绑定的质量门禁会阻止非经典配置成为默认值。
- 知识库设置页和 RAG 评估页会展示 Profile V2 就绪状态、门禁决策、指标增量和阻塞原因。

## 兼容性

- 未指定检索配置的现有客户端继续使用 `CLASSIC`。
- 现有 `VECTOR`、`HYBRID` 和 `RERANK` 行为不会被替换。
- QA 生成失败会回退到源文档路径，不会导致摄取失败。
- 共享 Profile V2 索引就绪后，切换配置不会触发再次重建。
- V1.4 的上传治理、恢复、稀疏迁移、RBAC、审计和可靠队列契约保持不变。

## 升级说明

- Flyway 升级到 V18、V19 和 V20。
- API 和 Worker 必须配置相同的专用 `MILVUS_PROFILE_COLLECTION`。
- 现有知识库需要执行一次滚动重建，使其达到 `index_schema_version=2` 并生成当前 `index_revision`。
- 在 Profile V2 就绪且候选配置的当前质量决策为 `PASSED` 之前，不要激活非经典默认配置。
- 请阅读 [V1.5.0 发布手册](v1.5-release-runbook.md)，尤其是 Legacy 清理和回滚约束。
